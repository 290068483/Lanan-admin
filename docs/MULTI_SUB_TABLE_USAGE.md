# 代码生成器多子表配置使用说明

## 1. 概述

本功能扩展了若依代码生成器，使其支持配置多个子表的一对多关系。通过在前端界面添加多子表配置区域，用户可以为一个主表关联多个子表，突破了原来只能关联单个子表的限制。

### 1.1 背景
lanan项目是一个基于SpringBoot+Vue3前后端分离的Java快速开发框架，代码生成器是其重要功能模块之一。标准的若依代码生成器只支持单个子表的配置，为了满足更复杂的业务需求，我们扩展了该功能以支持多子表配置。

### 1.2 适用范围
本文档适用于使用lanan项目代码生成器进行多子表配置的开发人员。

## 2. 功能特点

1. 支持单子表(1对1)和多子表(1对多)两种配置模式
2. 通过开关切换配置模式，同时只能存在一种模式
3. 单子表模式下保持与原有配置方式一致
4. 多子表模式下支持为一个主表配置多个子表
5. 每个子表可独立配置关联的外键字段
6. 保持与原有单子表配置的向后兼容性
7. 配置信息自动保存和恢复
8. 正确回显已保存的配置模式和子表配置
9. 在修改页面中正确显示已保存的配置
10. 修复了修改页面中开关选择和子表数据回显不正确的问题
11. 支持subTableType字段，用于区分一对一和一对多关系
12. 修复了subTableType字段的回显问题，确保配置模式正确显示

## 3. 使用步骤

### 3.1 选择生成模板

在代码生成器配置页面，选择"主子表（增删改查）"模板。

### 3.2 选择配置模式

在关联信息区域，通过"配置模式"开关选择需要的模式：
- 单子表(1对1)：使用传统的单子表配置方式
- 多子表(1对多)：支持配置多个子表

### 3.3 配置子表关系

根据选择的配置模式进行相应配置：

#### 3.3.1 单子表模式配置
1. 选择关联的子表名称
2. 选择关联的外键字段

#### 3.3.2 多子表模式配置
1. 点击"添加子表"按钮
2. 为每个子表配置项选择关联的子表名称
3. 为每个子表配置项选择关联的外键字段

### 3.4 移除子表配置

- 单子表模式：直接更改选择即可
- 多子表模式：点击对应配置项后的删除按钮

### 3.5 保存配置

点击"提交"按钮保存配置信息。系统会自动将子表配置序列化并存储。

### 3.6 回显配置

当重新打开已配置的表时，系统会根据已保存的配置自动选择正确的模式并回显子表配置：
- 如果之前配置了多个子表，则自动选择多子表模式
- 如果之前只配置了一个子表，则自动选择单子表模式
- 在修改页面中正确显示已保存的配置

## 4. 技术实现

### 4.1 数据存储

子表配置信息通过以下字段存储在数据库中：
- `subTableName`: 子表名称（单子表模式下使用，多子表模式下存储第一个子表名称）
- `subTableFkName`: 子表外键名称（单子表模式下使用，多子表模式下存储第一个子表外键名称）
- `subTableNames`: 多个子表名称，以逗号分隔（多子表模式下使用）
- `subTableFkNames`: 多个子表外键名称，以逗号分隔（多子表模式下使用）
- `subTableType`: 子表关系类型（1-一对一，2-一对多）

### 4.2 接口数据变更

当调用 `/tool/gen/{tableId}` 接口获取代码生成信息时，返回的数据结构中将包含上述字段。

### 4.3 提交数据变更

当通过 `/tool/gen` 接口提交修改后的代码生成信息时，需要在提交的数据中包含相应的字段。

### 4.4 核心文件

- `src/views/tool/gen/genInfoForm.vue` - 前端界面组件，包含配置模式开关和子表配置区域
- `src/views/tool/gen/editTable.vue` - 数据保存处理，负责将子表配置信息提交到后端

## 5. 前端实现细节

### 5.1 界面组件

在`genInfoForm.vue`中添加了以下组件：
1. "配置模式"单选框组 - 用于切换单子表/多子表模式
2. 单子表配置区域 - 包含子表名称和外键字段选择器
3. 多子表配置区域 - 包含"添加子表"按钮和表格组件
4. 表格组件 - 用于展示和编辑多个子表配置项
5. 选择器组件 - 用于选择子表名称和外键字段

### 5.2 数据处理

前端通过以下方式处理子表配置：
1. 使用`subTableMode`变量存储当前配置模式（1:单子表, 2:多子表）
2. 使用`subTableConfigs`数组存储多个子表配置项（仅多子表模式下使用）
3. 通过监听配置模式变化，在模式切换时正确处理数据转换
4. 通过监听`subTableConfigs`的变化，动态更新`subTableNames`和`subTableFkNames`字段
5. 在组件初始化时根据已保存的配置数据正确设置模式和初始化子表配置
6. 监听`info`属性变化，确保在数据加载后正确初始化配置模式
7. 通过强制触发响应式更新确保界面正确显示配置数据
8. 使用`subTableType`字段来区分和保存配置模式（1-一对一，2-一对多）
9. 修复了subTableType字段的回显问题，确保在修改页面中能正确显示已保存的配置模式

### 5.3 兼容性处理

为了保持与原有系统的兼容性：
1. 保留原有的`subTableName`和`subTableFkName`字段
2. 在单子表模式下，使用原有字段存储配置信息
3. 在多子表模式下，将第一个子表的配置信息同时存储到原有字段中以保持兼容性
4. 当从多子表模式切换到单子表模式时，自动将第一个子表配置填充到原有字段中
5. 当从单子表模式切换到多子表模式时，使用已保存的配置数据初始化多子表配置
6. 通过`subTableType`字段来标识当前配置模式，确保前后端数据一致性

## 6. 注意事项

1. 由于后端未修改，生成的代码仍然只支持一个子表。如需完整的多子表支持，需要手动修改生成的代码。
2. 子表配置信息在页面刷新后会自动恢复。
3. 添加的子表配置项需要同时选择子表名称和外键字段才会被保存。
4. 配置模式切换时会自动处理数据转换，但建议在切换前确认当前配置。
5. 系统能够正确回显已保存的配置模式和子表配置，不会出现模式重置的问题。
6. 在修改页面中能够正确显示已保存的配置，包括配置模式和子表配置信息。
7. 修复了修改页面中开关选择和子表数据回显不正确的问题。
8. 将后端验证错误转换为用户友好的消息提示，避免直接抛出异常。
9. 系统通过`subTableType`字段来区分一对一和一对多关系，确保配置模式的正确性。
10. 修复了subTableType字段的回显问题，确保在修改页面中能正确显示已保存的配置模式。

## 6.1 错误处理

当用户在配置子表信息时未正确填写必填字段（如关联子表的表名或外键名），后端会返回验证错误。系统现在会将这些错误转换为用户友好的消息提示，而不是直接抛出异常，提升用户体验。

例如，当用户未选择关联子表的表名时，系统会显示"关联子表的表名不能为空"的提示消息，而不是直接抛出未捕获的异常。
